herdr 工作流遷移 · Lesson 0002

每個 agent 一個 worktree：worktree create / open / remove

約 15 分鐘 · 先備：Lesson 0001（agent 協作 loop） · 版本：herdr 0.9.3

Mission 要的是多 agents 平行開發。Lesson 0001 讓你指揮 agent，但兩個 agents 共用同一個 checkout 時，branch 切換、build 產物會互踩。解法 herdr 原生就有：一個 worktree = 一個 workspace = 一條 branch，多 agents 各自平行、互不干擾。

你已經在用這個 pattern你的 appkernel 專案已手動維護多個 git worktrees（appkernel_ATEST_8947、appkernel_GTK、appkernel_review）。herdr 把這個手動流程產品化——本課最後還會教你把既有 worktrees 收編成 managed workspaces。

已驗證本課 drill 於 2026-10-05 在你的機器完整跑過（create → close → open → remove → branch 清理），教材輸出皆為真實執行結果。

1worktree workspace 是什麼

就是帶 Git checkout 來源的普通 workspace（官方文件）。普通 workspace 能做的它全都能：focus、rename、close、開 tabs/panes、跑 agents。差別只有一個：它知道自己從哪個 repo、哪條 branch checkout 出來，並與 parent repo 的 workspace 自動分組（sidebar 裡看得到從屬關係）。

2worktree create 一句話做五件事

herdr worktree create --cwd ~/personal/dotfiles --branch teach-0002 --label teach-0002 --no-focus

這一條指令（CLI reference）：

  1. 建 Git worktree checkout（目錄預設在 ~/.herdr/worktrees/<repo>/<branch-slug>，可由 config [worktrees] directory 改）
  2. 開一個新 workspace（含第一個 tab 與 root pane，cwd 直接指到 checkout）
  3. 與 parent repo 的 workspace 分組
  4. branch 已存在 → checkout 該 branch；不存在 → 從 --base（預設 HEAD）建立
  5. 回傳 JSON：.result.workspace、.result.tab、.result.root_pane——下一步要用的 ID 都在裡面

真實回應（節錄自你的機器）：

{"result":{"type":"worktree_created",
  "workspace":{"workspace_id":"wN","label":"teach-0002","number":3,
    "worktree":{"branch":"teach-0002","repo_root":"/home/syntec/personal/dotfiles",
                "checkout_path":"/home/syntec/.herdr/worktrees/dotfiles/teach-0002"}},
  "root_pane":{"pane_id":"wN:p1","cwd":"/home/syntec/.herdr/worktrees/dotfiles/teach-0002"}}}
與 Lesson 0001 接軌create 回傳 root_pane 的 pane ID——直接 herdr agent start builder --kind opencode --pane wN:p1，就是「每個 agent 一條 branch 平行開發」的完整形。create 與 agent start 是兩個明確步驟（agent start 永遠不自己建 pane）。

3生命週期：close ≠ open ≠ remove

指令herdr statecheckout 目錄branch
workspace close <id>關閉保留保留
worktree open --branch重新接上（新 workspace ID，ID 不重用）沿用既有沿用既有
worktree remove --workspace <id>關閉刪除（跑 git worktree remove；dirty 才需 --force）保留——要手動 git branch -d
危險區workspace close <id> --group 會連坐：關掉 primary workspace 加上它全部連動的 worktree workspaces（內建 skill 明文警告）。永遠不要為了繞過 workspace_group_close_required 加這個 flag。另外 --trust-repository 是 per-request 的 Git trust 授權，不是worktree 指令失敗時的常規重試選項。
查 list 要明確不帶參數的 herdr worktree list 以focused workspace 的 repo 為範圍——你的機器上它列出的是 appkernel（當時 focus 在 wH）。批次/腳本中一律用 --cwd <path> 或 --workspace <id> 明確指定，別依賴 focus（同 Lesson 0001 安全守則）。

4隨堂測驗

5實戰：完整生命週期跑一遍

在普通 shell 執行（用你的 dotfiles repo 當白老鼠）。過程盯 sidebar：新 workspace 會出現、消失、再出現（換新 ID）。

  1. 建立： 
    herdr worktree create --cwd ~/personal/dotfiles --branch teach-0002 --label teach-0002 --no-focus
    預期：type:"worktree_created"，root_pane 的 cwd 在 ~/.herdr/worktrees/dotfiles/teach-0002
  2. 驗證 Git 觀點： 
    git -C ~/personal/dotfiles worktree list
    預期：主 checkout 之外多一行 linked worktree，branch teach-0002 指向與 main 相同的 commit
  3. close 只關 state（記下 step 1 回傳的 workspace_id，示範設為 wN）： 
    herdr workspace close wN
git -C ~/personal/dotfiles worktree list   # checkout 還在！
  4. open 重新接上——注意是新 workspace ID（ID 不重用）： 
    herdr worktree open --cwd ~/personal/dotfiles --branch teach-0002 --no-focus
    預期：新 ws（我們跑的時候是 wP，你的會不同），cwd 指回同一個 checkout
  5. remove + branch 清理（remove 不刪 branch，收尾要兩步）： 
    herdr worktree remove --workspace <step-4的ws-id>
git -C ~/personal/dotfiles branch -d teach-0002

加分題（收編既有 worktrees）：把你在 appkernel 的手動 worktree 變成 managed workspace——

herdr worktree open --cwd ~/personal/windows_projects/appkernel --path ~/personal/windows_projects/appkernel_GTK --no-focus

收編後 sidebar 直接看得到它，也能對它跑 workspace/pane/agent 全套指令。用完 workspace close 即可（checkout 是你自己的，別跑 remove）。
