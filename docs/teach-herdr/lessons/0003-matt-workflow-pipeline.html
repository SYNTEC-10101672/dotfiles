herdr 工作流遷移 · Lesson 0003

Matt 工作流 × herdr：每張 ticket 一個 worktree、一個 agent

約 20 分鐘 · 先備：0001 agent 協作 loop + 0002 worktree workspaces · herdr 0.9.3

這是 mission 的具象化：你已經有規劃工具（Matt 的 /to-spec、/to-tickets、/implement、/code-review）和執行基礎設施（agent prompt/wait + worktree workspaces）。本課把它們焊成一條管線：規劃在主 checkout，實作散到 N 個 worktree × N 個 agents，你只審核與收斂。

已驗證整條管線於 2026-10-05 在你的機器上用真 ticket 跑通（/implement 經 agent prompt 遞送、絕對路徑讀 ticket、worktree 產出、策略 (b) 未 commit）。教材輸出皆為真實執行結果。

1管線總覽

規劃期（主 checkout，一個 agent 就夠）：

/to-spec      # 對話 → spec，存 .scratch/<feature>/spec.md
/to-tickets   # spec → tickets，一檔一票 .scratch/<feature>/issues/NN-<slug>.md（含 blocking edges）

實作期（逐張 unblocked ticket）：

  1. 為 ticket 開 worktree workspace（branch 命名 <feature>-NN 對應 ticket 編號）： 
    herdr worktree create --cwd ~/personal/dotfiles --branch myfeat-01 --label myfeat-01 --no-focus
  2. 在 root pane 啟動實作 agent： 
    herdr agent start impl-01 --kind opencode --pane <root_pane_id>
  3. 派工——slash 指令 + 絕對路徑 ticket： 
    herdr agent prompt impl-01 "/implement /home/syntec/personal/dotfiles/.scratch/myfeat/issues/01-slug.md" --wait --timeout 180000
  4. agent 回頭問問題時（--wait 返回 blocked）： 
    herdr agent read impl-01 --source recent-unwrapped --lines 80
herdr agent send-keys impl-01 <回答 UI 所需的鍵>
  5. 審核（策略 b：變更未 commit，躺在 worktree 裡等你）： 
    git -C ~/.herdr/worktrees/dotfiles/myfeat-01 status --short
git -C ~/.herdr/worktrees/dotfiles/myfeat-01 diff
  6. 收斂：滿意 → 在主 checkout merge 該 branch 並自己 commit（/commit）；不滿意 → 對 agent 追派修改（回到步驟 3）
  7. 清理： 
    herdr worktree remove --workspace <ws-id> --force   # 有未 commit 變更要 --force
git -C ~/personal/dotfiles branch -d myfeat-01
    ticket 檔案把 Status: 改為 resolved。

2Gotcha ①：`.scratch/` 不會出現在 worktree 裡

worktree 是從 HEAD checkout 出來的乾淨目錄——untracked 與 gitignored 的檔案都不會跟過去。而你的 issue tracker（.scratch/<feature>/）整個目錄是 gitignored（.gitignore 第 20 行）。所以：

規則派工時永遠給主 checkout 的絕對路徑（/home/syntec/personal/dotfiles/.scratch/...）。worktree agent 用絕對路徑讀得到（同一台機器、只是另一個目錄），但它自己找不到——相對路徑在它眼裡不存在。同場加映：worktree 裡也看不到主 checkout 未 commit 的變更（例如你今天寫到一半的筆記），agent 看到的是最後一個 commit 的世界。

3Gotcha ②：Commit Gate 是 per-session 授權

你的 commit-gate.ts 規則：AI 的 git commit 在未授權 session 一律擋下，/commit 授權只作用於該 session、不繼承、不跨 agent。管線裡每個 worktree agent 都是獨立 session，所以有兩條路：

策略做法代價
(a) 各自授權到每個 worktree agent 的 TUI 跑一次 /commit授權散落、review 介入點多
(b) 集中收斂（你選的）ticket constraints 寫明「不要 commit」；你在主 checkout 統一 review + /commit收斂是你的手動步驟

實測證據策略 (b) 實測：agent 完成後回報——「未 commit：ticket 明確要求不執行 git commit，你會在主 checkout review 後統一 commit。檔案以 untracked 狀態留在這個 worktree」——連偏離 /implement 預設行為的說明都自動附上。把 constraint 寫進 ticket 就夠了。

5隨堂測驗

6實戰：跑一次真管線

驗證用的 ticket 還在你的機器上：.scratch/teach-0003-pipeline/issues/01-demo-ticket.md。在普通 shell 逐段執行：

  1. 開 worktree + 啟動 agent： 
    wt=$(herdr worktree create --cwd ~/personal/dotfiles --branch teach-drill --label teach-drill --no-focus)
ws=$(printf '%s\n' "$wt" | jq -r '.result.workspace.workspace_id')
pane=$(printf '%s\n' "$wt" | jq -r '.result.root_pane.pane_id')
herdr agent start impl-drill --kind opencode --pane "$pane"
  2. 派工（絕對路徑！）： 
    herdr agent prompt impl-drill "/implement /home/syntec/personal/dotfiles/.scratch/teach-0003-pipeline/issues/01-demo-ticket.md" --wait --timeout 180000
    預期：tab 標題變成「Implementing work from 01-demo-ticket.md」；約一分鐘返回 done
  3. 審核（策略 b）： 
    git -C ~/.herdr/worktrees/dotfiles/teach-drill status --short
cat ~/.herdr/worktrees/dotfiles/teach-drill/docs/PIPELINE-DEMO.txt
    預期：?? docs/PIPELINE-DEMO.txt，內容「herdr × Matt pipeline 教學驗證 2026-10-05」
  4. 清理（這是練習，不做 merge）： 
    herdr worktree remove --workspace "$ws" --force
git -C ~/personal/dotfiles branch -d teach-drill
何時用 /code-review步驟 3 審核時，除了自己看 diff，也可以對 worktree agent 追派：herdr agent prompt impl-drill "/code-review 從 main 到現在的變更" --wait，或乾脆在主 checkout 對 merge 前的 branch 跑——Matt 的 code-review skill 會開雙軸 sub-agents（Standards + Spec）。
