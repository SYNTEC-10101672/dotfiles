herdr 工作流遷移 · Lesson 0001

一個 agent 指揮另一個 agent：prompt、wait 與五狀態

約 15 分鐘 · 先備：herdr keybinding 與基礎設定（你已具備） · 版本：herdr 0.9.3

你的 mission 是讓多個 AI agents 在 herdr 裡自主協作。這堂課教你最核心的一件事：用四個指令，讓一個 agent（或你自己）命令另一個 agent 做事、等它完成、讀它的回覆。

已驗證本課的實戰練習於 2026-10-05 在你的機器上完整跑過一次（split → start → prompt → read → cleanup），輸出是真實的。

1兩種控制面：pane vs agent

herdr 把 automation 分成兩層 surface——官方文件的原則：

  • pane 指令：控制 raw terminal。跑指令、送 input、讀輸出。pane 裡不一定有 agent。
  • agent 指令：控制「被 herdr 認出的 coding agent」。herdr 會驗證 agent 身分、追蹤它的 lifecycle 狀態。

關鍵差別：agent start 只能在既有、可用 shell prompt 的 pane 上啟動 agent——它不會自己 split pane。所以「開 agent」永遠是兩步：先 pane split，再 agent start。

2五個 lifecycle 狀態

所有 agent 指令的等待與判斷都圍繞這五個狀態（官方定義）：

working agent 正在執行
blocked herdr 認出 approval / question / permission UI
idle 完成或等待中，且已被看見
done 完成但尚未被看見
unknown 有 agent，但 herdr 無法有信心分類

idle vs done兩者都代表「可接受 input」。done 只是那個 completion 還沒被 mark as seen——read 不會 mark seen，focus 才會（每個 TUI client 各自追蹤）。所以從 CLI 觀察時，完成的 agent 常顯示 done；你點過去 focus 之後才變 idle。記住：Sidebar 的 Done badge 和 CLI 看到的可能不同步，這是設計不是 bug。
blocked 是嚴格判定herdr 只在 pane 的 live bottom-buffer match 到已知 approval/question UI 時才標 blocked（官方說明）。「看起來卡住」不等於 blocked。狀態有問題時用 herdr agent explain <target> 查判定過程。

3TARGET：怎麼指到一個 agent

所有 agent 指令的第一個參數是 <TARGET>，只接受兩種東西（內建 skill file）：

  1. live agent 名稱：須符合 [a-z][a-z0-9_-]{0,31}，且在 live agents 中唯一。名稱跟著 pane 的目前 occupant，agent 結束時清掉。
  2. pane ID：如 wK:p2——正在承載該 agent 的 pane。

不接受 terminal ID，也不接受 opencode 這種 agent-kind 標籤（同名 agent 可能有好幾個）。

4核心 loop：四步

  1. split 出新 pane（回傳 JSON，用 jq 取 .result.pane.pane_id）
    split=$(herdr pane split --current --direction right --cwd "$PWD" --no-focus)
pane_id=$(printf '%s\n' "$split" | jq -r '.result.pane.pane_id')
  2. 在該 pane 啟動 agent 並命名
    herdr agent start trainee --kind opencode --pane "$pane_id"
    --kind 支援 25 種（claude、codex、opencode、cursor、amp…），-- 後面接 agent 原生參數。回傳前 herdr 會等到 agent 被偵測且 ready（預設 30 秒 timeout）。
  3. 派工並等待
    herdr agent prompt trainee "Review the current diff" --wait --timeout 120000
  4. 讀回覆
    herdr agent read trainee --source recent-unwrapped --lines 120

這就是 herdr 首頁說的「agents … prompt each other, and wait until another agent is genuinely blocked instead of firing keystrokes and hoping」的具體實作（官方 recipe）。

5--wait 的真實語意

agent prompt --wait 不是「送字串後等 idle」那麼簡單（官方語意）：

  1. 文字與 encoded Enter 以單一有序提交送出（遵守 bracketed-paste mode）。
  2. agent 已是 blocked → 立即回傳 agent_blocked，不送任何 input。此時先 agent read 看 UI，再決定送什麼鍵。
  3. agent 原本不是 working → herdr 給 5 秒觀察期，必須看到 working 或 blocked 動靜，否則回傳 agent_prompt_stalled。
  4. 看到動靜後，等第一個 settled state（預設 idle/done/blocked）。
注意wait 追蹤的是 lifecycle 狀態，不是單一 turn。如果 agent 本來就在 working，這個 turn 的完成就可能直接滿足等待。另外 timeout/stalled 不代表 prompt 沒送達——先 read 再決定，不要盲目重送。

等「別的 agent 真的卡住」用獨立的 wait：

herdr agent wait reviewer --until blocked --timeout 120000

--until 可重複（如 --until idle --until done）。低階互動（回答 blocked UI）用 agent send-keys <target> esc|enter|ctrl+c。

6隨堂測驗

7實戰：在你的 herdr 跑一次完整 loop

隨便挑一個 herdr pane 的普通 shell（不是 opencode 裡面），貼上執行。過程中盯著 sidebar，你會看到 trainee 的狀態變化——這正是 native agent observation 在工作。

  1. split pane 並啟動 trainee（opencode）： 
    split=$(herdr pane split --current --direction right --cwd "$PWD" --no-focus)
pane_id=$(printf '%s\n' "$split" | jq -r '.result.pane.pane_id')
herdr agent start trainee --kind opencode --pane "$pane_id"
    預期：JSON 回傳 agent_status:"idle"、interactive_ready:true
  2. 派一個無害任務並等待： 
    herdr agent prompt trainee "這是一個 herdr 教學驗證。請只回覆：OK" --wait --timeout 120000
    預期：回傳 agent_status:"done"（不是 idle——你還沒 focus 過去 mark as seen！）
  3. 讀回覆： 
    herdr agent read trainee --source recent-unwrapped --lines 60
    預期：在輸出中找到 "OK"（讀太少行會只看到 TUI footer，這是 --lines 的用處）
  4. 清理自己開的 pane： 
    herdr pane close "$pane_id"
安全守則背景工作一律 --no-focus（別搶使用者的 focus）。ID 從 JSON response 解析，不要用 sidebar 順序猜。沒有自己建立的 workspace/tab/pane 不要關。herdr server stop 會殺掉所有 panes——沒有明確意圖永遠不要跑。
